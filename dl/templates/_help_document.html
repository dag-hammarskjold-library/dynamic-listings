Dynamic Listings — Help & documentation

Dynamic Listings (DL) builds and maintains HTML tables of UN library data—Security Council meetings, General Assembly resolutions, and the Veto List—stored in MongoDB. Operators sign in to review data, edit records where needed, export tables, and open public-style display pages.

Document version: September 2026

1. Overview

From the Dashboard you can open these modules:

  • Users — manage application accounts (email and password).
  • Security Council — SC meeting listings pulled from the Central Database (CDB) with refresh and manual edits.
  • GA Resolutions — General Assembly resolution listings with multilingual fields and refresh.
  • Veto List — Veto table maintained entirely in the application (no CDB refresh).
  • System Logs — audit trail of sign-ins and data changes.
Most listing data lives in MongoDB. Security Council and GA modules can be refreshed from CDB; the Veto List is updated only through the app or bulk HTML import (administrative scripts).

2. Getting started

Sign in

  1. Open the Dynamic Listings sign-in page.
  2. Enter your Email Address and Password.
  3. Click Sign In. You are taken to the dashboard when credentials are valid.

Use Toggle Theme in the sidebar (or the icon on the sign-in page) to switch light or dark mode. The choice is saved in your browser.

Sessions

You must stay signed in to open data modules. Use Logout in the sidebar when you finish.

4. Users

The Users module lists accounts stored in MongoDB. Typical tasks:

  • Add user — create an account with email and password.
  • Edit — update email or password for an existing user.
  • Delete — remove a user after confirmation.
Protect admin credentials. Password changes take effect on the next sign-in.

5. System logs

System Logs shows a chronological list of actions (sign-ins, listing updates, record creates/deletes). Use it to audit who changed data and when.

6. Security Council

Manage SC meeting listings for a selected year or listing id.

Common actions

  • Update the table — load records from MongoDB for the chosen listing.
  • Display — open a public-style HTML table in a new tab.
  • Refresh — pull newer data from CDB (when enabled for the listing).
  • Create / Edit / Delete — adjust individual meeting rows for the active language.
  • Full JSON — download the listing as JSON.

Editing is usually scoped to one language at a time (English, French, or Spanish), matching the language selector on the module page.

7. GA Resolutions

Works like Security Council for General Assembly resolution tables.

  • Choose a listing and language, then Update the table.
  • Resolution cells use prefix, link text, URL, and sufix fields (plus related columns for meeting, draft, title, date).
  • Refresh updates from CDB where configured.
  • Display, Extract to Excel, and Extract to HTML mirror the live table.

8. Veto List

The Veto List module has no CDB refresh. All rows are stored and edited in MongoDB.

Working with records

  1. Select listing (default sc_veto_list) and language.
  2. Click Update the table to load rows sorted by date (newest first).
  3. Use Create new record or the edit/delete icons on a row.

Creating a new record (example)

Use this walkthrough when adding a row by hand. The form title is Create record (EN), Create record (FR), or Create record (ES), depending on the language selector at the top of the page.

  1. Open Veto List from the sidebar.
  2. Set Choose listing: (usually sc_veto_list) and Language: to the language you are entering first (often English).
  3. Click Create new record.
  4. Fill the fields below, then click Create record.
  5. For French and Spanish, change Language:, click Update the table, open the same row with the edit icon, and click Update record after filling that language’s fields. The record id field (Record id (unique key, e.g. primary draft symbol S/2026/273)) stays the same across languages.

On create, only fields for the selected language are saved. Empty prefix, link text, URL, or sufix fields are allowed when a column has no link.

The table uses the same prefix, link text, URL, and sufix pattern as GA Resolutions (the form label is sufix, spelled as in the app). Text before the link goes in prefix; visible link wording in (link text); the href in link (URL); text after the link in sufix.

If the same cell needs both plain text and a link, put the leading text in prefix, the linked phrase in (link text), the URL in link (URL), and any trailing text in sufix. For a cell with multiple links, put the combined HTML-style content in the (link text) fields for that column (as after an HTML import), or split across prefix / link text / URL / sufix when a single link is enough.

If Create record fails with a message that the record already exists, choose a new Record id or edit the existing row instead. Use Sort date for table order; use Date for the text shown in the Date column.

Import from HTML

Click Import from HTML on the Veto List module page to upload the three table files (English, French, Spanish .htm). The app parses five-column rows, merges languages by row index, and inserts into MongoDB for the selected listing.

  • Dry run — parse and report counts without writing to the database.
  • Skip — if Veto_id already exists for the listing, leave the MongoDB row unchanged (default).
  • Update — if Veto_id exists, replace that record’s fields from the HTML row; new ids are inserted as usual.
  • Insert duplicate — always add a new row even when Veto_id already exists (can create duplicates; use with care).

The command-line script scripts/import_veto_from_html.py remains available for server-side file paths.

Field model

Column Stored fields (per language)
Date, Negative vote Single text/HTML field each (date_en, negative_vote_en, etc.).
Draft, Written record, Agenda item prefix, link text, link URL, and sufix. HTML import stores complex multi-link cells in the link text field when needed.

Display opens the published-style veto table (title, footnotes, five columns). Extract to Excel and Extract to HTML use the grid on screen.

Each record has a unique Veto_id (usually the main draft symbol, e.g. S/2026/273) and a sort date (YYYY-MM-DD) for ordering.

10. Refresh from CDB

Refresh on Security Council and GA Resolutions requests updated data from the DHL Central Database and merges it into MongoDB according to each module’s rules.

  • Allow time for the job to finish; watch notifications and system logs for errors.
  • Manual edits may be overwritten on fields marked for refresh—follow your team’s workflow before refreshing production listings.
  • Veto List records are never changed by refresh.

11. Troubleshooting

Cannot sign in

  • Confirm email and password. Ask an administrator to reset your password in Users.
  • Check that MongoDB is reachable from the application environment.

Table is empty after Update

  • Verify the correct listing id is selected.
  • For SC/GA, run Refresh if data should come from CDB.
  • For Veto List, confirm records exist for that listing in MongoDB.

Display page shows raw HTML or line breaks

  • Link columns use prefix, link text, URL, and sufix; plain columns store display HTML in the main field only.
  • Hard-refresh the browser if scripts or styles were updated recently.

PDF download fails

  • Ensure your network allows loading the PDF library from the CDN.
  • Use Print and choose “Save as PDF” in your browser instead.
